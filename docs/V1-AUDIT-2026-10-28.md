## Remaining closure gates

1. **Mobile visual/interaction QA is unverified in this audit.** The available browser
   has no documented viewport-resize/touch-emulation capability. The local QA host was
   unreachable from that browser; a data-URL frame was rejected by its security policy.
   No workaround was pursued after that rejection. CSS inspection and mocked touch tests
   are not equivalent to a real mobile browser. Owner should check at 375–430 CSS pixels:
   homepage/book placement, no sideways scrolling, all three readers, page buttons and
   swipe in both directions, Previous/Next installments, Archive and Continue Reading.
   Include a 320px-width check if available. Report any clipping, overlap or unreadable text.

2. **HTTP-to-HTTPS enforcement needs owner/admin confirmation.** Two HTTP-client checks
   of `http://www.katamisky.com/` returned HTTP 200 content without redirecting. Requests
   to the apex variants reached the canonical HTTPS URL. The HTTPS site itself is valid.
   The connector does not expose Pages-setting mutations; the browser's GitHub settings
   page is signed out. An owner must inspect repository Settings → Pages → Enforce HTTPS
   and enable it if unchecked, then verify the HTTP www URL redirects to HTTPS. Network
   measurements pass through an egress proxy, so a direct owner-side redirect check can
   also establish whether the observation is environment-specific. Do not change DNS,
   ownership or provider arrangements to address this setting.
